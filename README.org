#+title: video.el
#+author: 0WD0

* Start here

=video.el= displays images and plays video in graphical Emacs using Canvas
images.  GStreamer decodes media and plays audio; a native Emacs module supplies
frames to Canvas.  Use a dedicated =video-mode= buffer or put lazy inline video
in an ordinary buffer.  Linux is the primary target.  Canvas copies decoded
pixels into Emacs; it is not a zero-copy GPU sink.

** Requirements and build

- Emacs 32+ with dynamic modules and Canvas images, running on a graphical
  display.  Cairo is recommended.
- GStreamer 1.20+ with =gstreamer-play-1.0=, =gstreamer-app-1.0=, and
  =gstreamer-video-1.0= development packages; =libass= development files.
  Individual media formats also need their GStreamer decoder plugins.
- FFmpeg development libraries: =libavformat=, =libavcodec=, =libavutil= and
  =libswscale=, with the APNG demuxer and decoder enabled.  APNG uses these
  libraries in-process, not the =ffmpeg= command.
- A C11 compiler, =make=, and =pkg-config=.  =make test= additionally uses
  =gst-launch-1.0= and plugins for generating a VP8/WebM fixture, plus =zlib=
  development files for native APNG regression fixtures.
- Python 3 for explicit provisioning of the pinned dotLottie v0.1.58 C SDK.
  It is an external binary dependency, not a GStreamer plugin.

From this directory:

#+begin_src shell
make provision-dotlottie
make module
#+end_src

The Makefile looks for =emacs-module.h= under =/usr/local/include= by default.
If your Emacs installation uses another location:

#+begin_src shell
make EMACS_MODULE_INCLUDE=/path/to/include module
#+end_src

Put this directory (the Lisp files, =video-module.so=, and
=libdotlottie_rs.so=) on Emacs's =load-path=.  Loading starts no playback:

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/video.el")
(require 'video)
(video-open "/path/to/movie.webm")
#+end_src

For developer checks, run =make test= (ERT, compiling and a generated media
fixture) and =make check= (compiling, =checkdoc=, and loading the package).

* Viewing media

** Open a file or URI

#+begin_src emacs-lisp
(video-open "/path/to/photo.jpg")
(video-open-other-window "/path/to/movie.webm")
(video-open-other-frame "https://media.example/movie.mp4")
#+end_src

These return the media buffer.  =video-open= uses the selected window by
default; the other entry points override placement for that call.  All accept
=:kind= (=image= or =video=, inferred if omitted), =:buffer=, =:live=,
=:request-headers=, =:cache-file=, and =:cache-complete-function=.
=video-open= also accepts =:display-function=.  Use =:kind= when inference is
wrong.  A local image opened without =:buffer= visits the original file in
=video-image-mode=; other sources use a presentation buffer.  An existing
non-file =:buffer= can be reused, replacing its source while preserving each
window's viewport.  A file-visiting buffer cannot be used as a presentation
buffer.  Direct opening requires graphical Canvas support; it does not fall
back to Emacs's =image-mode= on decoder failure.

To select Canvas for *future* local image visits (including Dired), opt in:

#+begin_src emacs-lisp
(require 'video)
(video-image-auto-mode 1)
#+end_src

Disable it with =(video-image-auto-mode -1)=.  Remote image visits and visits
without graphical Canvas support retain native =image-mode=.  To associate
local videos, select their mode during file-mode dispatch rather than in
=find-file-hook= (so long-line protection does not process the binary file as
text):

#+begin_src emacs-lisp
(autoload 'video-file-mode "video" nil t)
(add-to-list 'auto-mode-alist
             '("\\.\\(?:mp4\\|mkv\\|webm\\)\\'" . video-file-mode))
#+end_src

=video-file-mode= and =video-image-mode= retain the file's bytes; panning and
zooming do not modify the buffer.  Revert reloads the decoder.  Save or revert
unsaved file changes before entering a Canvas file mode.  =C-c C-c=
(=video-image-native=) switches a Canvas image file back to native
=image-mode=; =M-x video-image-mode= switches it back.  Video file mode needs a
local file and graphical Canvas display.

With no application navigation callbacks, =n= / =p= cycle through local media
in the same directory.  A Dired visit uses that listing's order; other
visits use filename order.  =video-image-file-extensions= and
=video-video-file-extensions= determine which files are offered, not which
formats GStreamer can decode.  Old unmodified file/presentation buffers are
closed when navigation leaves them undisplayed.

** Dedicated viewer controls

| Keys / gesture          | Video                              | Image                           |
|-------------------------+------------------------------------+---------------------------------|
| =RET=                   | Play / pause                       | Pause / resume if animated      |
| =L=                     | Toggle repetition                  | Override animation loop policy  |
| =LEFT= / =RIGHT=        | Seek (=video-seek-step=)           | Pan                             |
| =S-LEFT= / =S-RIGHT=    | Seek (=video-long-seek-step=)      | —                               |
| =UP= / =DOWN=           | Adjust volume                      | Pan                             |
| =m=                     | Toggle mute                        | Toggle mute                     |
| =C-b/f/p/n=             | Pan viewport                       | Pan viewport                    |
| wheel / =C-wheel=       | Pan / pointer-anchored zoom        | Pan / pointer-anchored zoom     |
| =+= / =-=; =s=          | Zoom; set absolute percentage      | Zoom; set absolute percentage   |
| =0= / =1=; =W= / =H=    | Default fit / 100%; fit width / height | Same                        |
| =n= / =p=               | Next / previous media              | Next / previous media           |
| left drag / middle drag | Relative seek / pan                | Pan with middle drag            |
| =F=                     | Open / focus extra frame           | Open / focus extra frame        |
| =q= / =Q=               | Quit view / kill media buffer      | Quit view / kill media buffer   |

Transport controls on the Canvas support play/pause, seek, and mute.  A
left-button click without dragging toggles playback; dragging seeks with
paused frame previews where buffered media permits it.  One-finger drag pans,
two-finger pinch zooms, and tapping the media toggles playback.  Touching an
inline Canvas does not replace the host buffer's text scrolling.

Controls stay hidden on initial display and autoplay, including for paused
images.  Explicit transport interaction reveals them; they remain visible
while paused and disappear after =video-controls-hide-delay= during playback.
Hidden controls do not install transport hotspots over the host's image map.

With Evil loaded, =video-evil.el= installs Motion-state viewer bindings without
an evil-collection dependency: =hjkl= pan, =gj= / =gk= navigate, =p= or =RET=
toggle playback, =z0= resets fit, and =zo= selects 100%.  =0= and digits keep
Evil's motion/count behavior.  Other commands remain available via =M-x=.
The adapter loads whether Evil or =video= is loaded first; customize
=video-evil-enable-integration= or =video-evil-initial-state= as needed.

** Viewports, playback, and frames

A player owns the timeline and audio.  Each displayed window has its own
Canvas target and absolute pan/zoom viewport; splitting a window does not
start another decoder.  Resizing changes viewport size, not its chosen zoom.
=video-image-default-fit= defaults to =shrink= (do not enlarge small images),
while =video-default-fit= defaults to =contain=.  =0= reapplies the respective
fit; =1= displays at original size.  Panning is unconstrained, so media can
move completely out of view.

Transparent pixels and contain margins are composited against each surface's
display background before publication.  This works even when Emacs's Canvas
backend ignores alpha.  Background resolution follows each presentation's
display anchor, including text/overlay faces and buffer-local face remapping;
hosts do not supply a color callback.  Changing the background repaints a
paused image without decoding another frame.  Different presentations of one
player retain independent backgrounds.

Video ends unless looping is enabled.  =L= changes loop policy without
starting playback; looping needs seekable, non-live media.  For local animated
GIFs and APNGs, =video-animation-loop-policy= defaults to =file= (respect the
authored loop count, or play once without one).  =forever= and =once= are
alternatives.  APNG's =num_plays= is a total play count: 1 plays once and 0
loops forever.  A single-frame animation remains a still image; remote
animated images have no local loop metadata, so =file= plays them once.
An explicit =L= override belongs
to the player, not to a particular window.  At end of stream the player
pauses; playing again restarts an exhausted stream.

Local =.lottie= archives and genuine Lottie JSON use the same player, seek,
pause, loop, inline, and dedicated-viewer lifecycle.  The native renderer
publishes premultiplied frames directly through GstPlay's =appsrc= source;
no GIF or subprocess conversion is involved.  Arbitrary JSON and remote URLs
are not inferred as Lottie.  Opaque dotLottie cache files are recognized from
their ZIP manifest and v1/v2 animation directory entries.  Playback and poster
APIs infer the local source format; callers do not supply a decoder hint.
Visiting a JSON file still uses =json-mode=.
The source retains its authored dimensions and frame rate, so small inline
display dimensions alone do not reduce vector rasterization cost.

Local APNG files use the same player, inline targets, first-frame posters and
dedicated viewer.  Recognition reads the PNG animation header, including
files named =.png= or opaque cache files; ordinary PNGs remain still images.
Original frame delays, transparency, partial-frame blending and disposal are
preserved.  Seeking rebuilds frame dependencies from the beginning without
caching the decoded animation.  No GIF conversion, GStreamer modifications,
or global decoder-rank changes are needed.  APNG sources must be local files;
download remote APNGs before opening them.

Use =:live t= if the provider knows a stream is live but transport capability
detection does not.  Unseekable media displays =LIVE= instead of offering seek
controls.  Playback failures appear in a viewer's mode line; another =RET=
or play-button click explicitly retries the source.  Errors do not cause
automatic retries.

=F= opens an additional, reusable presentation frame with the same buffer and
playback but an independent viewport.  Its default =video-other-frame-parameters=
remove editor chrome and enable =no-special-glyphs= only in that frame.  =F=
or =q= *inside that frame* closes only the frame; =q= in an ordinary view
runs the application's quit callback, or =video-bury-buffer-function= when
there is none.  =Q= kills the media buffer and its presentation frames; other
presentations of a shared session can remain alive.

* Inline playback

=video-inline-insert= inserts a lazy occurrence into a writable host buffer.
It returns a =video-inline= object and starts no GStreamer pipeline until
activation:

#+begin_src emacs-lisp
(let ((poster (create-image "/tmp/poster.jpg")))
  (video-inline-insert "/tmp/movie.webm" poster 512 288
                       :fit 'cover :muted t))
#+end_src

With point on the occurrence, =RET= / =mouse-1= toggles playback, =m= mutes,
and =L= changes looping after initialization.  =C-RET= opens an ordinary
viewer; =F= opens or focuses a presentation frame.  =F= can prepare an
unstarted occurrence without autoplay.  The poster stays until the first
frame is presented.  =video-inline-prepare=, =video-inline-play=, and
=video-inline-present= offer the same operations to embedding code.

Removing an occurrence or killing its host releases its session lease.  The
player survives while another presentation still holds a lease.  Playback is
suspended when all targets are hidden if =video-pause-when-hidden= is non-nil;
this does not change the requested play/pause state.  Inline creation with an
explicit =:player= borrows it instead of taking ownership.

* Embedding API

** Player, session, and presentation lifetime

| Object                 | Responsibility                              | Closing it |
|------------------------+---------------------------------------------+------------|
| =video-player=         | Decode, clock, audio, buffering, seek state | Closes its targets |
| =video-session=        | Player plus inline/dedicated leases         | Closes its player and presentations |
| Dedicated buffer       | One lease (or a borrowed player)            | Releases that presentation |
| Inline occurrence      | One lease (or a borrowed player)            | Releases that occurrence |
| Window/Canvas target   | Viewport and frame presentation             | Does not close other targets |

Use =video-open= for an automatically playing view.  To retain one player's
position, audio, and progressive cache across surfaces, create a session.
=video-session-create= starts paused; neither =video-session-present= nor
=video-present-player= changes playback state:

#+begin_src emacs-lisp
(setq session (video-session-create "/tmp/movie.webm"))
(setq viewer (video-session-present session))
(video-player-play (video-session-player session))
#+end_src

=video-session-inline-create= attaches a session to a host-owned inline
occurrence; unlike =video-inline-insert=, it does not insert text or install
a poster overlay.  A custom host supplies its existing display marker or
overlay as =:anchor=, plus =:poster= and, if needed, =:activate-function=.
The anchor identifies the buffer and follows its display position; omitted,
the creation point in =:buffer= (or the current buffer) is used.  A session
with auto-close enabled (the default) closes its player when the last
presentation is released.  Close an unused session explicitly with
=video-session-close=.
Use =video-present-player= to show an existing player without transferring
ownership; close that player with =video-player-close= when finished.

For low-level playback without a host:

#+begin_src emacs-lisp
(setq player (video-player-create "/tmp/movie.webm" :volume 0.8))
(video-player-play player)
(video-player-seek player 30.0)
(video-player-pause player)
(video-player-close player)
#+end_src

=video-player-close= is idempotent.  =video-player-buffered-ranges= returns
locally available =(START . END)= intervals, or nil if the pipeline exposes
none.  =video-player-set-loop= and =video-player-toggle-loop= leave the
play/pause state alone.  Close players explicitly; native finalizers are a
last-resort cleanup path.

** Placement and application callbacks

=video-display-buffer-function= controls ordinary placement (same window by
default).  A one-off =:display-function= on =video-open= or
=video-session-present= receives a buffer and must return a live window; use
=video-display-buffer-other-window= or =video-display-buffer-other-frame=, or
supply your own function.  =video-pre-display-buffer-hook= and
=video-post-display-buffer-hook= run in the media buffer around display.
Bind =video-display-buffer-noselect= non-nil to avoid selecting the result.

Applications may set buffer-local =video-next-function=,
=video-previous-function=, and =video-quit-function=.  Reuse a non-file
=:buffer= when navigating a collection to keep the display window and each
window's viewport.  Do not change global display policy temporarily for a
single open call.

** Network sources

=:request-headers= takes an alist of HTTP name/value strings, applied to every
HTTP source for the media, including adaptive-stream child resources.
Malformed names and newline injection are rejected.  The caller is
responsible for redirect trust: do not pass credentials to untrusted origins.

=video-network-cache-size= bounds the temporary progressive-download ring
(default 64 MiB); zero disables it.  A network video may also specify
=:cache-file= for a persistent copy, promoted only when its progressive cache
is complete, and =:cache-complete-function= called with the player and local
filename.  Persistent caching requires progressive caching and applies only
to network video.  Formats without progressive download may expose no ranges
or complete cache.  =video-mouse-seek-seconds-per-pixel= controls relative
left-drag seeking.

* Limitations

- Recognized filename suffixes are not proof of decoder support.  PNG, JPEG,
  GIF, WebP, and SVG have been exercised with the development GStreamer
  installation; AVIF, TIFF, and BMP have not been reliable there.  Canvas
  decoder errors do not silently fall back to =image-mode=.
- Transparency uses one solid background color per surface, not arbitrary
  underlying images, gradients, or stipples.  Custom Canvas hosts can supply
  their background explicitly.
- EXIF orientation and color-profile fidelity are unverified.  Do not treat
  Canvas image mode as a complete replacement for native =image-mode=.
- In an ordinary Emacs window, redisplay reserves a terminal glyph column
  and may clip the Canvas's right edge.  The additional presentation frame
  uses =no-special-glyphs= to avoid this without changing other frames.
- Track selection and subtitle controls are not public interfaces yet.

See [[file:ARCHITECTURE.org][Architecture]] for the host/runtime boundary, render pipeline,
composite Canvas scenes, and the redisplay clipping explanation.
